# IMPROVEMENT_BACKLOG.md

Единственный источник правды о том, что делать следующей итерации Ralph
loop. Обновляется только агентом (в рамках итерации) или человеком вручную
между запусками. Статусы: `todo` / `in_progress` / `blocked` / `done` /
`reverted`.

Формат записи:

```
## [ID] Краткое название
- Статус: todo
- Приоритет: high | medium | low
- Источник: откуда взялась задача (конкретная запись в tuning_log / review_queue / ручное наблюдение человека)
- Гипотеза: что должно улучшиться и почему
- История: (заполняется агентом по мере попыток — что пробовали, что не сработало)
```

## [B001] Минимальный сквозной пайплайн для одной ЖС (вбд)

- Статус: in_progress
- Приоритет: high
- Источник: baseline-прогон `score_against_golden.py` от 2026-07-31 —
  Recall=0.000, Precision/AvgQS/PerfectRate=n/a по всем трём ЖС, потому
  что `revision_agent` пока не содержит кода извлечения (только
  `PROGRAM.md`). Точечные полевые фиксы невозможны — не на чем измерить,
  какое поле чаще ошибочно, если карточек нет вообще
- Гипотеза: собрать по структуре из `AGENTS.md` минимальный
  `create_deep_agent` (один tool поиска по allowlist + один subagent
  верификации, без гейта двойного подтверждения — его можно добавить
  позже) и прогнать его на ЖС "вбд" (12 мер в эталоне — наименьший лист,
  быстрее всего итерировать). Цель итерации — не 0.90 по всем метрикам,
  а просто ненулевой Recall/Match на вбд; это даст первый реальный
  сигнал по полям для следующих backlog-задач
- История: iteration_1 (2026-07-31) продвинула ОДНУ меру из 12
  (`revision_agent/pipeline.py::run_vbd_seed` + эвристика под
  aeroexpress.ru) — Match=1 на вбд, QS=0.333. Это НЕ полноценный B001:
  (1) нет LLM/deepagents, только ручная regex-эвристика под один
  конкретный сайт — не обобщается на другие 11 мер вбд без новых эвристик
  или замены на LLM-экстракцию; (2) [РЕШЕНО частично, см. B004/B005]
  `cntd.ru`/`mos.ru` недоступны напрямую из песочницы — через российский
  прокси пользователя (`revision_agent/pipeline.py:RU_PROXY_URL`) `cntd.ru`
  теперь реально фетчится (см. B004), а `mos.ru`/`gosuslugi.ru` — всё ещё
  нет (см. B005, похоже на требование ГОСТ-шифров в TLS); (3)
  categoryOfVeteran не извлекается — нет справочника соответствия
  формулировок НПА ("пп. 1-4 п. 1 ст. 3 ФЗ «О ветеранах»") категориальным
  меткам эталона ("Военнослужащие" и т.п.), это отдельная задача.
  Следующая итерация должна решить один из оставшихся пунктов, не все сразу.

## [B004] Извлечение карточки из cntd.ru через прокси (77_vbd_11/12/13, транспортный/земельный налог)

- Статус: todo
- Приоритет: high
- Источник: ручная проверка сети 2026-07-31 (см. `revision_agent/pipeline.py`,
  docstring) — с российским прокси пользователя + cookie jar (обязателен
  из-за SSO-редиректа через `auth.kodeks.ru`) `cntd.ru` реально отдаёт
  полный текст НПА (подтверждено на документе 3691928, Закон города
  Москвы №33 "О транспортном налоге", 200К+ символов). Это открывает
  доступ к основному allowlist-источнику НПА, который раньше считался
  недоступным
- Гипотеза (обновлена после iteration_3, см. историю): базовые законы
  (документы 3691928 — транспортный налог, 3656284 — земельный налог) НЕ
  содержат статьи со льготами вообще — нужно искать конкретную
  поправку/отдельный документ, устанавливающий льготу ветеранам, а не
  парсить уже открытую базовую страницу. Следующая попытка: полнотекстовый
  поиск (например через Yandex Search API — см.
  `auto/scripts/search_yandex.py` — или прямой запрос на consultant.ru
  через тот же прокси) вида "Закон города Москвы транспортный налог
  льгота ветеранам боевых действий", а не эвристика на уже известном URL
- История: **iteration_3 (2026-07-31, без коммита)** — зафетчил оба
  документа (3691928 полностью — 58681 симв., 3656284 — 75864 симв.)
  через `pipeline.fetch_text(use_proxy=True)`, искал "боевых действий",
  "ветеран", названия всех трёх категорий, "Статья 4", суммы льготы —
  **ничего не найдено ни в одном документе**. Оба текста содержат только
  определение объекта налогообложения и таблицы ставок, статьи льгот в
  них нет. `Пункт НПА1` у всех 6 мер в эталоне пустой — по всей видимости,
  эталон тоже цитирует только базовый закон, а не документ с самой
  льготой (см. `Обработка НПА.docx` п.3.1 про отсылки к другим НПА). Код
  не менялся, метрики не изменились — не commit/revert, а "информация
  собрана, гипотеза уточнена". Полный разбор:
  `data/output/ralph_iteration_20260731_115719.md`.

## [B005] mos.ru / gosuslugi.ru недоступны даже через прокси — похоже на требование ГОСТ-TLS

- Статус: todo
- Приоритет: medium
- Источник: ручная проверка сети 2026-07-31 — через прокси TCP-туннель до
  `mos.ru:443` устанавливается, но TLS-хендшейк падает с
  `SSL_ERROR_SYSCALL` сразу после `Client Key Exchange`/`Finished`
  (воспроизводится и с `--insecure`, то есть это не проблема доверия
  сертификату) — характерно для сайтов, требующих ГОСТ-шифросьюты,
  которые не поддерживает обычная сборка OpenSSL/LibreSSL.
  `gosuslugi.ru` не отвечает через прокси вообще (таймаут)
- Гипотеза: нужен TLS-клиент со сборкой `gost-engine` (или аналог) для
  mos.ru, и/или другой прокси/подход для gosuslugi.ru (возможно требует
  ещё и обхода anti-bot, не только сети). Это отдельная инфраструктурная
  задача, вероятно нужна пользовательская консультация по тому, чем
  реально будет исполняться агент в проде — GOST-TLS обычно решается на
  уровне окружения (спецсборка Python/OpenSSL), не на уровне кода одного
  скрипта
- История: —
