# IMPROVEMENT_BACKLOG.md

Единственный источник правды о том, что делать следующей итерации Ralph
loop. Обновляется только агентом (в рамках итерации) или человеком вручную
между запусками. Статусы: `todo` / `in_progress` / `blocked` / `done` /
`reverted`.

Формат записи:

```
## [ID] Краткое название
- Статус: todo
- Приоритет: high | medium | low
- Источник: откуда взялась задача (конкретная запись в tuning_log / review_queue / ручное наблюдение человека)
- Гипотеза: что должно улучшиться и почему
- История: (заполняется агентом по мере попыток — что пробовали, что не сработало)
```

  а просто ненулевой Recall/Match на вбд; это даст первый реальный

- История: iteration_1 (2026-07-31) продвинула ОДНУ меру из 12

  `cntd.ru`/`mos.ru` недоступны напрямую из песочницы — через российский

## [B006] Sandbox: `pyexpat`/`libexpat` ABI-рассинхрон блокирует `openpyxl` и весь `pip` — блокирует eval для ЛЮБОЙ задачи

- Статус: blocked
- Приоритет: high (не тюнинговая задача — инфраструктурный блокер самого
  eval-шага, выше любого backlog-item по метрикам)
- Источник: iteration_20260801_140738 (попытка продолжить B003 после
  того, как сетевой блокер iteration_5 был снят коммитом 409f6ef) —
  первый же шаг (`.venv/bin/python scripts/score_against_golden.py`)
  оказался невыполним в этой сессии: `.venv` не существовал (гитигнорен,
  создаётся заново в каждой сессии), а `python3 -m venv .venv` падает на
  `ensurepip` с `ImportError: Symbol not found:
  _XML_SetAllocTrackerActivationThreshold` (`pyexpat.so` собран против
  более новой `libexpat`, чем реально стоит в `/usr/lib/libexpat.1.dylib`
  на этой машине). Воспроизведено на python3.11/3.12/3.14 (все три
  Homebrew-сборки). Системный `pip 26.1` тоже падает на любой
  install/download той же цепочкой импортов
  (`pip._vendor.distlib.compat` → `xmlrpc.client` → `xml.parsers.expat`)
  — то есть блокер не только у `ensurepip`, а у pip вообще
- Гипотеза (для человека, не для следующей автономной итерации — это
  системное окружение машины/песочницы, не код репозитория):
  `brew reinstall expat && brew reinstall python@3.12` (пересборка/
  релинковка), либо проверить конфликт путей библиотек через `otool -L`
  на `pyexpat.cpython-312-darwin.so`, либо это версионирование самого
  образа песочницы разошлось с тем, что было на момент iteration_4
  (когда eval точно работал — см. `tuning_log.jsonl`)
- История: **iteration_20260801_140738** — подтвердил, что это не
  проблема доставки пакета (скачал `openpyxl`/`et_xmlfile` wheel'ы
  напрямую curl'ом с pythonhosted.org в обход pip, распаковал вручную
  `zipfile`-модулем в `.venv/lib/python3.12/site-packages/` — импорт
  `openpyxl` всё равно падает на реальном XML-парсинге). Это подтверждает
  проблему именно в бинарной совместимости `pyexpat` с системной
  `libexpat`, не чинится на уровне Python/pip. Не пытался чинить через
  `brew` — это системное изменение вне репозитория, требует подтверждения
  человека (см. полный разбор в
  `data/output/ralph_iteration_20260801_140738.md`). **Пока этот блокер
  не снят человеком — Ralph loop не может прогнать eval вообще, ни на
  одной задаче.** Следующая автономная итерация должна первым делом
  проверить, снят ли этот блокер (`.venv/bin/python -c "import
  openpyxl"`), и если да — перейти к следующей `todo`/`in_progress`
  задаче как обычно.
