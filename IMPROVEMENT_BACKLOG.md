# IMPROVEMENT_BACKLOG.md

Единственный источник правды о том, что делать следующей итерации Ralph
loop. Обновляется только агентом (в рамках итерации) или человеком вручную
между запусками. Статусы: `todo` / `in_progress` / `blocked` / `done` /
`reverted`.

Формат записи:

```
## [ID] Краткое название
- Статус: todo
- Приоритет: high | medium | low
- Источник: откуда взялась задача (конкретная запись в tuning_log / review_queue / ручное наблюдение человека)
- Гипотеза: что должно улучшиться и почему
- История: (заполняется агентом по мере попыток — что пробовали, что не сработало)
```

## [B001] Минимальный сквозной пайплайн для одной ЖС (вбд)

- Статус: todo
- Приоритет: high
- Источник: baseline-прогон `score_against_golden.py` от 2026-07-31 —
  Recall=0.000, Precision/AvgQS/PerfectRate=n/a по всем трём ЖС, потому
  что `revision_agent` пока не содержит кода извлечения (только
  `PROGRAM.md`). Точечные полевые фиксы невозможны — не на чем измерить,
  какое поле чаще ошибочно, если карточек нет вообще
- Гипотеза: собрать по структуре из `AGENTS.md` минимальный
  `create_deep_agent` (один tool поиска по allowlist + один subagent
  верификации, без гейта двойного подтверждения — его можно добавить
  позже) и прогнать его на ЖС "вбд" (12 мер в эталоне — наименьший лист,
  быстрее всего итерировать). Цель итерации — не 0.90 по всем метрикам,
  а просто ненулевой Recall/Match на вбд; это даст первый реальный
  сигнал по полям для следующих backlog-задач
