## Гипотеза

Найти РЕАЛЬНУЮ меру поддержки инвалидов (не выдуманную, независимо от
эталона на старте поиска) и добавить первый seed по аналогии с
`run_svo_seed`/`run_vbd_seed` — `run_disability_seed` в
`revision_agent/pipeline.py`. Ожидаемый эффект: Match 2→3, Recall
0.040→0.060, Precision без изменений (1.000, т.к. если карточка не
матчится — это Miss_agent, не Error_agent), Average QS/Perfect Rate —
композиционный эффект (см. прецедент iteration_4), не обязаны расти.

Процесс поиска (для трассировки, не для подгонки): фетч через
`fetch_text(use_proxy=True)` (прокси уже подтверждённо работает с
cntd.ru — см. PROGRAM.md, инфраструктурная запись 2026-07-31 01:10) двух
московских НПА, которые фактически цитирует эталон для меры "77_1"
("Компенсация лицу, занятому уходом за ребёнком-инвалидом или инвалидом
с детства в возрасте до 23 лет"): базовый закон (document/3662941, "О
социальной поддержке семей с детьми") и постановление о размерах выплат
на 2026 год (document/1314770295). Эталонная строка использована ТОЛЬКО
как список кандидатов-источников для проверки (та же методологическая
оговорка, что и в iteration_1/iteration_4 — независимого реестра мер
пока нет) — сама карточка строится из независимо прочитанного текста
источников, не переписывается из эталона.

Найдено при фетче (детали — в docstring
`extract_disability_care_compensation_card`):
- Базовый закон перечисляет вид выплаты по названию (ст.7 п.1 пп.3), но
  НЕ содержит ни суммы, ни условий назначения.
- Постановление о размерах (п.1.3.1) даёт ровно число `17790` для этой
  строки — без разбивки по группе инвалидности и без разбивки по причине
  инвалидности (это ОДНО число на весь вид выплаты).
- Условия назначения (кто из родителей/опекунов) и ведомство ни разу не
  упомянуты ни в одном из двух источников — вероятно, это с mos.ru
  (недоступен из песочницы, см. B005). `measureTerms`/`department`
  оставлены `None`, не угадываются.

Методологическое решение (документировано в коде): т.к. постановление
не вводит разбивку ни по группе инвалидности, ни по причине инвалидности
для ЭТОЙ строки (структурный факт текста, а не выбор "чтобы совпало с
эталоном"), `cause_*` и `measure_*_group` заполняются одинаково
(1 / 17790) — трактовка "нет разбивки = применяется независимо от
группы/причины", а не "данных нет". Это отличается от прецедента
`categoryMobilized=0` в `extract_svo_college_meal_card`: там текст
ПЕРЕЧИСЛЯЕТ конкретные категории и не называет одну из них (признак
исключения), здесь текст в принципе не вводит такую группировку (признак
отсутствия ограничения). Осознаю, что это менее консервативно, чем
предыдущие два seed'а, — фиксирую рассуждение явно, чтобы следующая
итерация могла его оспорить, если оно окажется неверным на других мерах.
