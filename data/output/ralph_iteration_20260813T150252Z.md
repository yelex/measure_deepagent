# Ralph iteration — L011 regression fix

- Задача: [L011] контентный fallback-триггер `has_relevant_content`
  (статус: `blocked — регрессия, приоритет critical`, см.
  `IMPROVEMENT_BACKLOG.md` → "[ANALYST 2026-08-13] Root-cause").
- Baseline (метрика перед этой итерацией, из `tuning_log.jsonl` последней
  валидной записи, коммит `7e687b2`, note="scorer-lemma-restored"):
  Recall=0.860 Precision=1.000 AvgQS=0.371 PerfectRate=0.000 (43 карточки).
  По ЖС: вбд AvgQS=0.311, сво AvgQS=0.294, инвалиды AvgQS=0.448.
  ВАЖНО: этот прогон был ДО коммита 051a2e2 (L011-код, экспорт которого
  сейчас лежит в data/output/agent_cards_export.json и содержит
  регрессию — 21/21 инвалиды и 14/16 сво карточки пустые заглушки).
  Формально это последний известный НЕ-регрессивный baseline для
  сравнения.
- Диагноз Analyst'а (2026-08-13, зафиксирован в backlog): код L011
  (051a2e2) добавил `no_relevant_content` триггер в
  `run_pipeline_demo.py::run_llm_mode`, использующий
  `has_relevant_content()` из `llm_extract_v2.py`. Задача L011 изначально
  была сформулирована как фикс "для cntd.ru" (JS-рендеринг отдаёт только
  оголовок закона), но реализация применила триггер безусловно ко ВСЕМ
  доменам всех ЖС. Для документов, посвящённых ОДНОЙ конкретной мере
  (частый случай для "сво"/"инвалиды", mos.ru/cntd.ru), ключевое слово
  меры оказывается только в преамбуле (позиция < 3000) и не повторяется
  дальше — эвристика ошибочно считает корректно загруженный документ
  нерелевантным и форсирует fallback на `search_and_fetch_npa` (Yandex
  Search API, L008). Это резко увеличило число вызовов API; к обработке
  "инвалиды" (последний ЖС по порядку в реестре) поиск, видимо, исчерпал
  квоту/начал возвращать пустые результаты — отсюда каскад пустых
  карточек-заглушек.
- Гипотеза: если ограничить применение `no_relevant_content`-триггера
  доменом `cntd.ru` (как изначально задумано в постановке L011, см.
  `IMPROVEMENT_BACKLOG.md` секция L011 "Действие (было)"), то ложные
  срабатывания для mos.ru/mosgortur.ru/sp53.mos.ru/disk.yandex.ru
  (источники "сво"/"инвалиды") исчезнут, каскад вызовов
  `search_and_fetch_npa` вернётся к норме, и AvgQS/Recall для
  "сво"/"инвалиды" восстановятся к уровню, близкому к baseline (или
  лучше — cntd.ru-специфичный фикс остаётся в силе для ВБД).
- План проверки: правка `run_pipeline_demo.py::run_llm_mode` —
  вычислять `no_relevant_content` только если `urlparse(url).netloc`
  содержит `cntd.ru`, иначе `False` (полагаться только на
  `too_short`/`MIN_TEXT_LENGTH`, как было до L011-коммита для всех
  остальных доменов). Прогнать полный batch (`--llm-mode`, синхронно) +
  `score_against_golden.py`, сравнить AvgQS/Recall с искажённым текущим
  экспортом (0.241 итого по анализу Analyst'а) и с довирусным baseline
  (0.371). Убедиться, что "инвалиды"/"сво" карточки больше не пустые
  заглушки (field-count > 3 в большинстве случаев).
