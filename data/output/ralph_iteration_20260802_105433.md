## Гипотеза
Эталонная строка `77_12` ("Региональная компенсация инвалидам на
технические средства реабилитации", ТСР) перечисляет 7 конкретных
предметов (столик прикроватный, стул для ванны и душа, сиденье для
ванны, ступенька для ванны, насадка на унитаз, доска для ванны, доска
для пересаживания) — уникальный, легко проверяемый набор токенов для
полнотекстового поиска. Оба уже фетчащихся источника (закон 3662941,
постановление 1314770295) проверены полнотекстовым поиском на эти
термины — 0 совпадений, нужен новый источник. WebSearch нашёл
`mos.ru/otvet-zdorovie/kak-poluchit-kompensaciyu-za-pokupku-sredstv-reabilitacii-dlya-invalida/`
(обычная otvet-FAQ-страница mos.ru, тот же паттерн, что и для
77_7/8/9/11) — вручную проверено через `fetch_text(use_proxy=True)`, что
все 7 предметов присутствуют дословно (4 повторения в разных блоках
FAQ), плюс явное упоминание "Департамента труда и социальной защиты
населения" рядом с этой темой (совпадает с эталонным department).
Golden `measure_first/second/third_group`/`measure_disabled_child` = не
число, а слово "компенсация" (variable-per-item сумма, нет фиксированной
цифры) — `sum_field_match` в scorer'е делает fallback на
`text_field_match`, когда `extract_number` не находит цифр ни у агента,
ни в эталоне, так что буквальное совпадение строки "компенсация" по всем
4 подполям должно пройти агрегированный `sum_match`.
