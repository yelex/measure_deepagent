# Ralph iteration 2026-08-13 16:15 UTC — Coder pass

## Задача
[L013] Обработка исчерпания квоты/rate-limit GLM в батч-пайплайне
(приоритет critical, статус todo). Выбрана как высший приоритет todo:
L011 — уже in_progress (код закоммичен, ждёт eval-подтверждения, не
задача Coder'а трогать заново), L013 явно помечена Analyst'ом как
блокирующая доверие к результату L011-фикса.

## Baseline
Последний честный tuning_log-прогон: L003 (2026-08-12), AvgQS=0.322,
Recall=0.860, Precision=1.000 (43 карточки). Прогон 2026-08-12 23:15
(после L009+L011) дал регрессию AvgQS→0.241, но корневая причина —
не баг экстракции, а необработанный HTTP 429 "Usage limit reached for
5 hour" от GLM начиная с середины ЖС "сво": `_call_glm_structured`
делает 2 бесполезных ретрая по 3с, затем возвращает ошибку, которую
`run_llm_mode` тихо превращает в карточку-заглушку
`{measureId, region, measureName}` — неотличимо от других причин
пустой карточки в экспорте.

## Гипотеза
Если явно распознавать 429+"Usage limit"/code 1308 как отдельный тип
ошибки (`GLMQuotaExceededError`) и останавливать batch целиком при
первом таком случае (вместо продолжения с заглушками), то:
1. Eval на частичном экспорте будет явно недостоверен для
   необработанного remainder (сигнал в консоли + exit code 2), а не
   молча похож на регрессию экстрактора.
2. Будущие Coder/Tester-проходы смогут отличить "прогон, оборванный
   квотой" от "прогон с реально худшей экстракцией" без грепа логов
   постфактум — ровно то, чего не хватило в инциденте с L011.

## Изменения
- `revision_agent/llm_extract_v2.py`: новый класс
  `GLMQuotaExceededError(RuntimeError)`. В `_call_glm_structured` при
  `HTTPError` с `code==429` и телом, содержащим `"Usage limit"` или
  `"code":"1308"`, — поднимаем это исключение немедленно, без ретраев
  (retry гарантированно бесполезен против 5-часового окна).
- `scripts/run_pipeline_demo.py::run_llm_mode`: отдельный `except
  GLMQuotaExceededError` вокруг вызова `extract_measure_via_llm` —
  печатает явное сообщение, ставит `quota_exceeded=True`, прерывает
  оба цикла (`ls`, `seed`), пишет частичный экспорт как есть (не
  заглушки на весь остаток) и завершает процесс с `sys.exit(2)` с
  сообщением "N/M карточек обработано, экспорт частичный".
