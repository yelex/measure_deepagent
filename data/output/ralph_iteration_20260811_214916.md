## Выбор тестовой меры
`77_vbd_4` "Бесплатный проезд на аэроэкспрессе" (source:
aeroexpress.ru/aero/info/benefits.html) — самая изученная карточка в
проекте (первый e2e-срез, iteration_1), сейчас extraction через
`extract_vbd_aeroexpress_card` (regex), QS известен по разбору.

Предварительная ручная проверка (до кодовых изменений): золотой
`department` = `"Кассы «Аэроэкспресса»"`. Полнотекстовый поиск по
реально зафетченному тексту источника (`fetch_text(...)`, 15049 симв.)
показывает, что точная словоформа `"Кассы «Аэроэкспресса»"` **в тексте
источника не встречается вообще** — есть только `"в кассах"`
(предложный падеж мн.ч.) и `"кассу «Аэроэкспресс»"` (винительный падеж +
именительный бренда). Золотой эталон здесь — авторская нормализация
человеком, не дословная цитата. Это значит: даже идеальный
grounded-экстрактор (обязана цитата дословно из текста, как в v1 и v2)
принципиально не может воспроизвести эту точную словоформу без нарушения
grounding-гейта — совпадение по `text_field_match` (Jaccard/ratio без
лемматизации) для этого конкретного поля этой конкретной карты
маловероятно ни для regex, ни для LLM.

## Гипотеза
LLM v2 (`llm_extract_v2.extract_measure_via_llm`) на том же исходном
тексте всё равно может дать выигрыш относительно текущего regex на ДРУГИХ
полях этой карточки, которые сейчас `null` из-за отсутствия
эвристики/недостаточно общего regex: `categoryOfVeteran`, `measureSum`,
`measurePeriodicity`, `measureTerms` (сейчас все `null` — см. текущий
экспорт: только `department` заполнен, причём неверно по эталону).
Т.к. `department` с высокой вероятностью не улучшится (см. выше —
структурное ограничение golden/scorer, не движка), ожидаемый эффект —
рост AvgQS этой ОДНОЙ карточки за счёт полей помимо `department`, а не
100%-й QS.

Проверка: заменить в `revision_agent/pipeline.py::run_vbd_seed` ветку
для `aeroexpress.ru` на вызов `llm_extract_v2.extract_measure_via_llm`
вместо `extract_vbd_aeroexpress_card`, перегенерировать экспорт, прогнать
`score_against_golden.py`, сравнить `AvgQS` по ЖС "вбд" (сейчас 0.531 на
6 картах) и overall AvgQS/Recall/Precision. Успех — рост `вбд` AvgQS без
падения Recall/Precision (Match не должен исчезнуть — measureName от
LLM не трогаем, он остаётся из seed).

Если regex-версия окажется не хуже (or LLM не даст прироста) —
`git checkout` отката правки в pipeline.py, backlog `B008` → история
дополняется, статус остаётся `in_progress` (шаг 1 не подтверждён, но и
не "reverted trying same thing" — это первая реальная попытка шага 1,
не третья подряд).
