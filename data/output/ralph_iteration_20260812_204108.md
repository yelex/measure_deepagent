## Диагностика (эта итерация)

Прогнал `score_against_golden.py --no-log` и сравнил конкретные
golden vs agent значения для department/terms по всем "Match"-карточкам
(см. лог сессии). Находки:

1. **department для "сво"/"инвалиды" — не задача извлечения из текста.**
   Golden почти всегда = константа: "Единый центр поддержки участников
   СВО и их семей" (сво, 15/16 карточек) или "Департамент труда и
   социальной защиты населения Москвы" (инвалиды, default для большинства).
   Эти строки физически отсутствуют в текстах конкретных НПА (указ
   8-УМ не упоминает "Единый центр поддержки") — это факт единого окна
   обслуживания меры, а не атрибут акта. LLM с grounding-проверкой
   принципиально не может его извлечь из текста источника. Не чиню в
   этой итерации (отдельная задача — статический lookup по ЖС, не
   входит в объём L003), но фиксирую находку в PROGRAM.md.

2. **terms/None для части "сво"-карточек — баг контекстного окна,
   не промпта.** 12 из 16 "сво"-seed'ов используют ОДИН общий источник
   (docs.cntd.ru/document/1300860766, указ 8-УМ, 26908 симв. после
   fetch). `run_pipeline_demo.py::run_llm_mode` обрезает текст до
   `source_text[:12000]` ДО вызова экстрактора — контент по некоторым
   мерам физически теряется. Дальше `_cut_to_relevant()` внутри
   `llm_extract_v2.py` ищет позицию по `measure_name.split()[:3]`
   точным substring-совпадением — для русского языка с падежными
   окончаниями это часто мажет (пример: имя меры "Бесплатная юридическая
   помощь", в тексте — "юридическИМ вопросам", "юридическУЮ помощь";
   точное "юридическая" не встречается ни разу). При провале поиска
   ключевых слов `_cut_to_relevant` берёт произвольное окно text[3000:8000],
   which может не содержать нужный пункт указа вообще.

## Гипотеза

Если (а) убрать преждевременную обрезку `source_text[:12000]` в
`run_pipeline_demo.py` (передавать в экстрактор весь текст, окно
всё равно ограничивается `_cut_to_relevant(window=8000)` дальше по
цепочке) и (б) заменить точное substring-совпадение ключевых слов на
сравнение по стеммированному префиксу (первые 6 символов слова, что
покрывает большинство русских падежных окончаний) — то доля
None/пропущенных `measureTerms` для "сво" снизится, что должно поднять
AvgQS хотя бы для ЖС "сво" (сейчас 0.263), не ухудшив вбд/инвалиды.
